## ⚙️ Configuration

### 1. Vite Alias Configuration (main.ts)

Following Storybook's monorepo guidelines, we configure Vite aliases to resolve internal packages:

```typescript
async viteFinal(config: InlineConfig) {
  return {
    ...config,
    resolve: {
      ...config.resolve,
      alias: {
        ...config.resolve?.alias,
        '@dsai/tokens': resolve(__dirname, '../../@dsai/tokens/src'),
        '@dsai/tokens/css': resolve(__dirname, '../../@dsai/tokens/dist/css'),
        '@dsai/tokens/js': resolve(__dirname, '../../@dsai/tokens/dist/js'),
      },
    },
  };
}
```

**Why?** In monorepos, relative paths like `../../@dsai/tokens/dist/css/variables.css` fail during Vite's module resolution. Aliases provide clean, absolute paths.

### 2. CSS Import (preview.ts)

```typescript
import '@dsai/tokens/css/variables.css';
```

**Why?** Uses the Vite alias configured in `main.ts` for clean, maintainable imports.

### 3. Pre-build Scripts (package.json)

```json
{
  "scripts": {
    "prestorybook": "pnpm --filter @dsai/tokens build",
    "storybook": "storybook dev -p 6006",
    "prebuild": "pnpm --filter @dsai/tokens build",
    "build": "storybook build -o ./storybook-static"
  }
}
```

**Why?** Ensures design tokens are always built before Storybook starts, preventing missing CSS file errors.

## 🚀 Usage

### Development

```bash
# From workspace root
pnpm nx storybook storybook

# Or from storybook package
cd packages/@dsai/storybook
pnpm storybook
```

**What happens:**

1. `prestorybook` hook runs → builds tokens
2. `storybook dev` starts → imports fresh CSS
3. Opens at `http://localhost:6006`

### Production Build

```bash
pnpm nx build storybook
```

**What happens:**

1. `prebuild` hook runs → builds tokens
2. Static site generated to `storybook-static/`

## 📚 Writing Stories

### Color Documentation Example

```tsx
import tokens from '@dsai/tokens';

export default {
  title: 'Foundation/Colors',
  parameters: {
    layout: 'fullscreen',
  },
};

export const AllColorHues = () => {
  return (
    <div>
      {Object.entries(tokens.color || {}).map(([hue, shades]) => (
        <div key={hue}>
          <h3>{hue}</h3>
          {Object.entries(shades).map(([shade, token]) => (
            <ColorSwatch
              key={`${hue}-${shade}`}
              name={shade}
              value={token.value}
              cssVar={`--dsai-color-${hue}-${shade}`}
              token={`color.${hue}.${shade}`}
            />
          ))}
        </div>
      ))}
    </div>
  );
};
```

**Key Points:**

- Import tokens from `@dsai/tokens` (uses package exports)
- Access token values via `.value` property
- CSS variables are auto-generated by Style Dictionary

## 🔧 Troubleshooting

### Error: "Failed to fetch dynamically imported module"

**Cause:** CSS file not found or incorrect Vite alias configuration.

**Fix:**

1. Ensure tokens are built: `pnpm --filter @dsai/tokens build`
2. Check `main.ts` viteFinal configuration
3. Verify import path in `preview.ts` uses alias

### Error: "Colors showing as #cccccc"

**Cause:** Accessing token object instead of `.value` property.

**Fix:**

```tsx
// ❌ Wrong
<div style={{ background: tokens.color.blue['50'] }}>

// ✅ Correct
<div style={{ background: tokens.color.blue['50'].value }}>
```

### Stale Cache Issues

**Fix:**

```bash
# Kill Storybook
pkill -9 -f storybook

# Clear caches
rm -rf .nx/cache
rm -rf node_modules/.vite

# Rebuild and restart
pnpm tokens:build
pnpm nx storybook storybook
```

## 🎯 Best Practices

### 1. Always Use Aliases

```typescript
// ✅ Good
import '@dsai/tokens/css/variables.css';
import tokens from '@dsai/tokens';

// ❌ Avoid
import '../../../@dsai/tokens/dist/css/variables.css';
```

### 2. Build Tokens First

Always run token build before Storybook (handled by pre-hooks).

### 3. Follow Story Naming

```
Foundation/
  Colors
  Typography
  Spacing
Components/
  Button
  Input
```

### 4. Use MDX for Documentation

```mdx
import { Meta } from '@storybook/blocks';

<Meta title="Foundation/Colors" />

# Color System

Our color palette follows WCAG 2.1 AA guidelines...
```

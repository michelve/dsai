# Button Component Guide

The DSAi Button is a powerful, accessible button component with **Finite State Machine (FSM)** driven visual state management. This guide covers best practices, accessibility patterns, and advanced usage.

## Core Concepts

### Finite State Machine (FSM)

The Button uses an FSM to manage visual states consistently:

```
States: idle → hovered → focused → pressed → disabled → loading → error
```

**Benefits:**

- ✅ Predictable state transitions
- ✅ No conflicting visual states
- ✅ Consistent across all interactions
- ✅ Fully testable (36 dedicated FSM tests)

### State Diagram

```plaintext
                    ┌──────────────────────────────────────┐
                    │              disabled                │
                    └──────────────────────────────────────┘
                           ↑              ↓
    ┌──────┐  ENTER   ┌─────────┐  LEAVE   ┌──────┐
    │ idle │ ───────→ │ hovered │ ───────→ │ idle │
    └──────┘          └─────────┘          └──────┘
       ↓                   ↓
    ┌─────────┐       ┌─────────┐
    │ focused │       │ pressed │
    └─────────┘       └─────────┘
                           ↓
                    ┌──────────────────────────────────────┐
                    │          loading / error             │
                    └──────────────────────────────────────┘
```

## Loading States

### Basic Loading

```tsx
const [isLoading, setIsLoading] = useState(false);

<Button
  loading={isLoading}
  onClick={() => {
    setIsLoading(true);
    // ... async operation
    setIsLoading(false);
  }}
>
  Submit
</Button>;
```

### With Loading Text

```tsx
<Button loading={isLoading} loadingText="Saving...">
  Save Changes
</Button>
```

### Loading State Callbacks

Handle async operation lifecycle with FSM callbacks:

```tsx
<Button
  loading={isLoading}
  onLoadingComplete={() => {
    // Called when loading completes
    showToast('Operation successful!');
  }}
  onError={() => {
    // Called on error state
    showToast('Something went wrong');
  }}
>
  Process Data
</Button>
```

## Accessibility

### Icon-Only Buttons

**Always provide `aria-label` for icon-only buttons:**

```tsx
// ✅ Good - has aria-label
<Button aria-label="Close dialog" variant="outline-secondary">
  ×
</Button>

// ✅ Good - has aria-label for icon
<Button aria-label="Go to next page" startIcon="→" />

// ❌ Bad - missing accessible name
<Button variant="outline-secondary">×</Button>
```

### Screen Reader Announcements

Use `announce` and `announceText` for dynamic state announcements:

```tsx
<Button
  loading={isLoading}
  announce={true}
  announceText={isLoading ? 'Saving your changes' : 'Changes saved'}
>
  Save
</Button>
```

### Keyboard Navigation

All buttons support full keyboard navigation:

- `Enter` / `Space` - Activate button
- `Tab` - Move focus to next element
- `Shift + Tab` - Move focus to previous element

### ARIA Attributes

```tsx
// Toggle button
<Button
  aria-pressed={isActive}
  aria-expanded={isOpen}
  aria-controls="menu-panel"
>
  Toggle Menu
</Button>

// Loading state (auto-managed)
<Button loading>
  {/* aria-busy="true" and aria-disabled="true" are auto-applied */}
  Processing
</Button>
```

## Error States

Handle operation failures gracefully:

```tsx
const [status, setStatus] = useState<'idle' | 'loading' | 'error'>('idle');

<Button
  loading={status === 'loading'}
  error={status === 'error'}
  errorText="Failed to save"
  onError={() => {
    // Log error, show notification, etc.
  }}
  onClick={async () => {
    setStatus('loading');
    try {
      await saveData();
      setStatus('idle');
    } catch {
      setStatus('error');
    }
  }}
>
  Save Changes
</Button>;
```

## Disabled State

```tsx
// Static disabled
<Button disabled>Cannot Click</Button>

// Conditional disabled
<Button disabled={!isValid || isLoading}>
  Submit Form
</Button>
```

> ⚠️ **Note:** Avoid passing `onClick` to disabled buttons. The CLI analyzer will warn you about this pattern.

## Form Integration

### As Submit Button

```tsx
<form onSubmit={handleSubmit}>
  <Button type="submit" loading={isSubmitting}>
    Submit
  </Button>
</form>
```

### With Form Validation

```tsx
<Button type="submit" disabled={!formIsValid} loading={isSubmitting}>
  {isSubmitting ? 'Submitting...' : 'Submit'}
</Button>
```

## Best Practices

### Do's ✅

1. **Always provide accessible names for icon-only buttons**
2. **Use loading states for async operations**
3. **Handle error states gracefully**
4. **Use semantic button types** (`button`, `submit`, `reset`)
5. **Keep button text concise and action-oriented**

### Don'ts ❌

1. **Don't use buttons for navigation** (use links instead)
2. **Don't disable buttons without explanation**
3. **Don't use icon-only buttons without `aria-label`**
4. **Don't pass onClick to disabled buttons**
